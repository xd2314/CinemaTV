# Security reporting

Do not post private keys, passwords, full device backups, exploit payloads or personal device records in public Issues.

If the repository has GitHub private vulnerability reporting enabled, use **Security → Report a vulnerability**. If that option is unavailable, request a private contact from the maintainer without disclosing exploit details. The owner must enable this channel before publishing; no private mailbox is invented in this template.

Include the affected source version, general Android/API version, minimal synthetic reproduction, expected/actual behavior and whether the issue involves Root, file providers, exported components or signing. Use scrubbed examples, never another person's media credentials or identifiers.

Current support is the latest public source branch, on a best-effort basis with no guaranteed response time. This does not assert that all older APKs or vendor firmware are secure. Root operations and plaintext ADB can affect the whole device; retain confirmations and recovery boundaries.
